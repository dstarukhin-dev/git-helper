## ✨ Возможности
- **Клонирование репозиториев** - поддержка HTTPS-ссылок с возможностью указания учётных данных
- **Гибкое добавление файлов** - три режима работы:
  - Добавление всех изменений (`git add -A`)
  - Добавление конкретных файлов по имени
  - Выбор файлов из интерактивного списка изменений
- **Создание коммитов** - с обязательным указанием сообщения
- **Отправка изменений** - `git push` с поддержкой автоматической аутентификации
- **Управление учётными данными** - сохранение и автоматическое использование логина и пароля
- **Цветной вывод** - для лучшей читаемости
- **Обработка ошибок** - информативные сообщения и проверки

## 📦 Требования
- **Bash** 4.0 или выше
- **Git** 2.0 или выше
- Права на выполнение скриптов

## 🚀 Установка
### 1. Скачивание скрипта
### Создайте директорию для скриптов (опционально)
    mkdir -p ~/bin

### Скачайте проект
    git clone https://praktikum.gitlab.yandexcloud.net/s11877154/My-GIT-Helper.git
или
    https://praktikum.gitlab.yandexcloud.net/s11877154/My-GIT-Helper/-/archive/master/My-GIT-Helper-master.zip

 - Если Вы скачали с помощью GIT - скопируйте скрипт в ~/bin
 - Если Вы скачали архив проекта - распакуйте скрипт в ~/bin

Настройте права:

    chmod +x ~/bin/git-helper.sh

### Добавьте в ~/.bashrc или ~/.zshrc
    export PATH="$HOME/bin:$PATH"

Затем выполните команду для применения изменений:

    source ~/.bashrc

## 💻 Использование
Запуск скрипта

    ./git-helper.sh

Или, если добавлен в PATH:

    git-helper.sh

## 🎯 Меню и функции
### Навигация по меню
Используйте клавиатуру для выбора пунктов меню:
 - Введите номер пункта (0-5) и нажмите Enter.
 - Для возврата к меню после выполнения операции нажмите Enter.

0. Выйти - Завершает работу скрипта.

1. Клонировать репозиторий - Клонирует удалённый репозиторий по HTTPS-ссылке.

Пример использования:

Введите HTTPS-ссылку на репозиторий: https://praktikum.gitlab.yandexcloud.net/s11877154/My-GIT-Helper

Опционально: можно указать учётные данные для приватных репозиториев.

2. Добавить изменённые файлы - Добавляет файлы в индекс Git для последующего коммита.

Варианты:
 - Все изменения - добавляет все изменённые файлы.
 - Конкретные файлы - ввод имён файлов через пробел.
 - Выбрать из списка - интерактивный выбор из нумерованного списка.

Пример выбора из списка:

Список изменённых файлов:
  1. src/main.py
  2. README.md
  3. config/settings.json

Введите номера файлов для добавления: 1 3

3. Сделать коммит - Создаёт коммит с указанным сообщением.

Пример:

Введите сообщение коммита: Fix bug in authentication module

4. Запушить изменения - Отправляет локальные коммиты в удалённый репозиторий.

Особенности:
 - Автоматически использует сохранённые учётные данные
 - При отсутствии данных предлагает ввести их вручную
 - Поддерживает автоматическую аутентификацию

5. Настроить учётные данные - Настраивает сохранение логина и пароля для автоматической аутентификации.

Пример:
 - Введите имя пользователя: myusername
 - Введите пароль: [скрытый ввод]
 - Сохранить учётные данные для будущих сессий? (y/n): y

## 📋 Новые возможности работы с тегами:
### Просмотр всех тегов
 - Показывает все теги с указанием типа (лёгкий/аннотированный)
 - Сортировка и цветовое выделение
 - Подсчёт общего количества тегов

### Создание нового тега
 - Лёгкий тег - простой указатель на коммит
 - Аннотированный тег - с сообщением и метаданными (рекомендуется для релизов)
 - Проверка на существование тега с таким именем

### Удаление тега
 - Удаление только локально
 - Удаление локально и в удалённом репозитории
 - Интерактивный выбор из списка

### Просмотр информации о теге
 - Тип тега (лёгкий/аннотированный)
 - Сообщение (для аннотированных)
 - Хеш коммита
 - Дата создания
 - Автор
 - Связанный коммит

### Отправка тегов в удалённый репозиторий
 - Отправка всех тегов (git push --tags)
 - Отправка конкретного тега (выбор из списка)

### Скачивание тегов из удалённого репозитория
 - git fetch --tags - загрузка всех тегов из удалённого репозитория
 - Показывает обновлённый список после загрузки

## 🔐 Настройка учётных данных
Учётные данные сохраняются в файле ~/.git_credentials с правами доступа 600 (только для чтения владельцем).

### Ручная настройка
Вы можете создать файл вручную:

    echo "GIT_USERNAME='your_username'" > ~/.git_credentials
    echo "GIT_PASSWORD='your_password'" >> ~/.git_credentials
    chmod 600 ~/.git_credentials

### Удаление сохранённых данных
    rm ~/.git_credentials

### Использование с Git Credential Helper
Скрипт автоматически настраивает временное кэширование пароля:

    git config --local credential.helper 'cache --timeout=3600'

## 🔒 Безопасность
### Меры предосторожности
Хранение паролей - пароли хранятся в открытом виде в файле ~/.git_credentials.

Рекомендуется:
 - Ограничить доступ к файлу (владелец только для чтения).
 - Использовать на личных, доверенных машинах.
 - Не передавать файл другим пользователям.

Временные файлы - скрипт создаёт временные файлы в /tmp/, которые автоматически удаляются.

### Ручная очистка при необходимости
    rm -f /tmp/git_pass_*
